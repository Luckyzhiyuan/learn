# 智能数仓平台 —— 实施路线图（对标补齐 v1.3）

> 前置：v1.0 已交付智能开发核心闭环（元数据 / 建模 / SQL助手 / 质量 / 检索问答 / 调度基础 / 表级血缘 / RAG / 通知 / LLM网关 / 认证）。
> 本文基于《智能数仓平台-功能开发文档》v1.3（F1-F15）与里程碑 M4~M6，给出可落地的分阶段实施路线图，功能编号与功能开发文档保持一致。

| 阶段 | 目标口号 | 覆盖功能 | 是否硬门槛 |
|------|---------|---------|-----------|

## 1. 阶段1：安全合规底座（P0，上线硬门槛）

**一句话**：把"能跑"变"能合规上生产"。无权限/脱敏/审计则平台不可信；无字段级血缘则改表不可控。

### 1.1 F8 数据安全（先落，独立无前序）
- **目标**：敏感识别 + 脱敏 + 权限(RBAC/表级/字段级) + 审计四件套。
- **依赖**：无（仅基于现有 `sys_user`）。
- **涉及**：
  - 表：`sys_role`、`sys_user_role`、`sys_perm_point`、`data_level`、`mask_rule`、`audit_log`、`data_app`（申请审批）
  - 接口：`/roles`、`/users/{id}/roles`、`/permissions`、`/audit-logs`、`/mask-rules`、`PUT /tables/{id}/data-level`、`/data-apps`
  - 配置：`PERM_ENABLED`、`AUDIT_ENABLED`
- **交付物**：
  1. RBAC 中间件/依赖：`get_current_user` 升级为「鉴权 + RBAC 鉴权」，新增 `require_permission(res, action)`。
  2. 行/列级权限：`perm_point` 按 `res_type+res_id` 判定；查询加工时注入行级谓词 / 列裁剪。
  3. 脱敏策略引擎：按 `data_level` → `mask_rule` 匹配字段做动态脱敏；敏感识别打标。
  4. 审计切面：写 `audit_log`（登录/查询/发布等），由 service 层埋点。
- **验收要点**：未授权用户访问受控表返回 403；越权列被脱敏或剔除；审计能查到"谁何时用什么 SQL 访问哪张表"。

### 1.2 F1.6 字段级血缘 + 影响分析（依赖 F1 元数据）
- **目标**：血缘从表级细化到字段级，能回答"改这个字段会影响哪些下游"。
- **依赖**：F1 元数据（已就绪）、F6 任务（解析 SQL 触发）。
- **涉及**：
  - 表：`field_lineage`（复用 `meta_lineage.field_level`）
  - 接口：`POST /lineage/field/build`、`GET /tables/{id}/impact?depth=N`、`GET /fields/{id}/lineage`
  - 错误码：`40023`
- **关键设计**：sqlglot 提取 select/where/join 列映射 → `field_lineage`；`meta_lineage`+`field_lineage` 建图 → 目标 BFS 反向遍历输出影响子图。
- **验收要点**：一条 `INSERT...SELECT` 能自动产出字段映射；对某字段改表能列全下游任务/表。

### 1.3 F6.5 SLA 时效与基线保障（依赖 F6 调度）
- **目标**：告警规则化 + SLA 时效性保障 + 任务健康分。
- **依赖**：F6（已就绪）、F8 权限（告警接收人可授权）。
- **涉及**：表 `sla_def`；接口 `PUT /sla`、`GET /monitor/alerts`；在 `notify_message` 基础上扩展告警通道。
- **验收要点**：任务超时 / 失败触发告警；SLA 逾期可识别并可分级别上报。

> **里程碑 M4 出口标准**：P0 三角（安全 / 字段级血缘 / SLA）全部落地并通过安全评审。

## 2. 阶段2：智能增强与数据资产（P1）

**一句话**：让"智能助手"长出"数据文化"——**先建指标与语义层作 AI 地基**，再以数据标准、资产、分析闭环固化。

### 2.1 F14.2 语义层（提前，AI 增强的架构地基）
- **说明**：由原规划提前。语义层是"AI 上台阶"的地基：先抽象 `semantic_model`（业务对象→表/字段/指标/权限），后续 F14.1 指标口径、F5.5 权限感知 NL2SQL、F14.3/14.4 都建立在它的统一语义之上。
- **目标**：用语义层弥合"业务语言 ↔ 物理表/字段"，让 NL2SQL 与问答表达更准确、口径更稳定。
- **依赖**：F1 元数据、F8 权限（语义模型含权限要素）。
- **关键设计**：`semantic_model` = 业务对象→(表/字段/指标/权限)；NL2SQL 以语义层解析为主、`optimize` 规则引擎兜底。
- **前置交付**：`semantic_model` 表结构与建模 API、语义解析器、与规则引擎兜底衔接。
- **验收要点**：同一业务提问稳定映射到一致的表/字段；口径调整不反向破坏下游 SQL 使用者。

### 2.2 F14.1 指标口径定义与画像（依赖 F14.2 统一语义）
- **目标**：统一指标口径（消除二义性），沉淀指标画像。
- **依赖**：F14.2（语义层提供统一语义/指标映射）、F1（表/字段）。
- **涉及**：
  - 表：`metric_def`、`metric_attr`（指标↔表/字段映射）
  - 接口：`CRUD /metrics`、`POST /metrics/{id}/validate`、`GET /metrics/{id}/lineage`、`POST /sql/review`
  - 错误码：`40022`（口径校验未通过）
- **验收要点**：同一指标不会有两种口径；指标画像聚合血缘/质量/owner/时效。

### 2.3 F5.5 权限感知 NL2SQL + 多轮会话（依赖 F8 权限 + F14.2 语义层）
- **权限感知**（依赖 F8）：生成时把用户行/列权限作为 prompt 约束，`finally` 对候选 SQL 做 SQL 级权限校验（越权拒绝）。
- **多轮会话上下文**（基础，见效快）：基于 `qa_conversation` 承载 session，携带最近 N 轮 + 命中表/知识库片段。
- **AI 增强取数出图**（后置，联动 F12）：复杂问题自动拆子查询；NL 直接出图。
- **验收要点**：多轮能正确澄清；越权取数被拦截；复杂问题能拆多步；NL 可直接生成图表。

### 2.4 F11 数据标准 + F12 数据分析 + F9 数据资产 + F10 数据开发
- **F11 数据标准**：标准定义 / 落标映射 / 数据字典 / 术语表（与知识库 `kb_alias`/`kb_document` 共用一套术语源头）。
- **F12 数据分析**：查询结果可视化、自助看板、导出（受 F8 脱敏约束）。
- **F9 数据资产**：资产目录 / 标签体系 / 收藏 / 统计，资产详情聚合血缘+质量+owner。
- **F10 数据开发**：SQL 编辑器（复用 F3）+ 脚本任务 + 发布上线，为 F3/F5 提供"安身之所"。

> **里程碑 M5 出口标准**：语义层与指标口径就位、数据标准统一、资产化闭环、AI 能"安全地懂业务"。

## 3. 阶段3：全域补齐（P2）

**一句话**：从"数据开发平台"走向"完整数据平台"。

### 3.1 F7 数据集成与数据源管理
- **目标**：多源注册 + 离线/增量同步。
- **依赖**：F1（目标元数据）、F6（调度同步任务）。
- **涉及**：表 `data_source`、`sync_task`；接口 `CRUD /data-sources`、`POST /data-sources/{id}/test`、`CRUD /sync-tasks`、`POST /sync-tasks/{id}/run`；错误码 `40024`。
- **验收要点**：能登记 JDBC/Hive/对象存储源、测试连通、配置全量/增量同步并调度运行。

### 3.2 F14.3 指标血缘 + F14.4 Copilot/Agent
- **F14.3 指标血缘**：指标 ↔ 口径 SQL ↔ 来源表/字段的血缘，回答"某指标怎么算、用了哪些源"。
- **F14.4 Copilot/Agent**：语义层之上的 Copilot（NL 直接生成指标查询、一键出图）；Agent 化多步任务（拆分意图→子查询→组装结果）。

### 3.3 F15 成本治理与资源管理
- **目标**：成本分析 + 资源组/队列/配额 + 小文件治理建议。
- **依赖**：F1（表/分区大小）、F6（运行实例统计）。
- **涉及**：接口 `GET /cost/report`、`CRUD /resource-groups`；联动小文件识别。
- **验收要点**：能看库/表成本趋势、给出降本建议、配置队列配额。

### 3.4 F13 数据服务/API + F6.6 工作流 DAG
- **F13 数据服务**：表→API 发布 + 访问控制 + 调用监控/限流 + 数据推送（试点最小闭环）。
- **F6.6 工作流 DAG**：以 DAG 编排任务依赖（复用 F6.3），串并行/分支、失败重跑。

> **里程碑 M6 出口标准**：覆盖数据集成→开发→治理→服务→可视化的完整闭环。

## 5. 依赖关系与关键路径

```
F8 数据安全(横切，最先) ────────────┐
F1 元数据/血缘 ──→ F1.6 字段级血缘/影响分析
F6 调度       ──→ F6.5 SLA ────────┼→（安全/治理底座，P0 出口）
F14.2 语义层(地基，提前) ──→ F14.1 指标口径 + F5.5 权限感知NL2SQL + F14.3/14.4(AI 增强)
F11 标准 + F9 资产 + F12 分析 ──→（资产与口径闭环，P1 出口）
F7 集成 + F8 发布 + F14.4 ──→ F13 API/可视化门户
F15 成本 ──→ 资源配额与治理
```

**关键路径**：F1 → F1.6（影响分析）与 F8（权限）并行可先行；**F14.2 语义层提前作为 AI 地基，再带动 F14.1 指标口径、F5.5 权限感知与 F14.3/14.4**；F7/F15/F13/F6.6 可并行于后。

## 6. 风险与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| 权限模型改动影响所有查询路径（NL2SQL/search/质量） | 高 | 以依赖注入 + 查询改写层统一收敛权限逻辑，先做列级再做行级 |
| 字段级血缘解析复杂 SQL 准确率 | 中 | 用 sqlglot 抽列映射 + 抽样标注校验，失败标注 `40023` 不阻断 |
| 指标口径统一依赖业务共识 | 中 | 先内置常用指标模板 + 审批流兜底 |
| 语义层周期长 | 中 | 语义层已提前，先落最小 `semantic_model`（表/字段/指标）骨架再增量扩充，避免一次性大工程 |
| 成本/同步涉及真实引擎成本 | 低 | 接入前做容量/成本评估，设配额 |

---

## 7. 优先投入建议

1. **第一期只做 P0（F8 + F1.6 + F6.5）**：任何功能若要上生产，安全/字段级血缘/告警缺一不可。
2. **P1 首选先落 F14.2 语义层最小骨架**：作为 AI 地基，先带 `semantic_model`（表/字段/指标）再扩充，后续 F14.1/F5.5/F14.3/F14.4 均受益。
3. **F5.5 多轮可作为"快赢"**：改动面小、演示效果强。
4. **F14.1 指标口径复用现有 optimizer 规则引擎做发布前校验**：成本最低、收益明确。
5. **F15 先做最小成本报表 + 小文件识别**，资源配额预留接口，避免前期过度投入。
