# 第一部分 · PRD（产品需求文档）

---

## 1. 产品概述

### 1.1 产品定位

**智能数仓平台** 是一个面向数据开发工程师与数据分析师的 Web 平台，以"元数据驱动 + 智能化辅助"为核心，覆盖数仓的**建模、开发、调度、质量、检索问答**全流程。平台强调"智能"，即把过去依赖人工经验的环节（元数据梳理、建表建模、SQL 优化、质量校验、口径查询）通过规则引擎 + 执行计划分析 + 自然语言交互等方式自动化、智能化。

### 1.2 产品愿景

让数仓开发者"少写重复代码、少踩性能坑、少手工查口径"，让数据分析师"会查会看会问"，通过智能能力提升数仓建设效率与数据质量。

### 1.3 产品范围（In / Out）

**In（本期范围，单团队试点）：**
- 元数据管理（Hive 建表语句读取、表/字段/血缘可视化）
- 智能建模（分层建模规范校验、建表 SQL 生成）
- SQL 智能开发助手（解析、优化、改写、校验）
- 数据质量（规则配置、异常检测、校验报告）
- 自然语言检索问答（NL2SQL / 口径查询）
- 调度（先用 Spark 自带，能力可插拔）

**Out（本期不做，后续迭代）：**
- 多数据源接入（本期仅 Hive，后续扩展 MySQL / Kafka / 云仓等）
- 多租户 / 权限治理的深度实现（本期单团队，做基础权限）
- 复杂调度编排平台（本期用 Spark 自带，调度框架单独立项）
- 数据资产对外商业化 / 数据服务化对外开放

### 1.4 名词定义

| 名词 | 定义 |
|------|------|
| 元数据 | 描述数仓数据的数据，如表结构、字段、分区、血缘、大小 |
| 血缘 | 数据从一个表/字段流向另一个表/字段的关系 |
| NL2SQL | 自然语言转 SQL |
| 数据质量规则 | 用于校验数据的规则（非空、唯一、值域、波动等） |
| 执行计划 | Spark 对 SQL 解析优化后生成的 Stage/Task 执行图 |

## 2. 目标用户与使用场景

### 2.1 目标用户画像

| 用户 | 核心诉求 | 典型操作 |
|------|----------|----------|
| **数据开发工程师** | 提效、避坑、保证质量 | 查看元数据、建表建模、写/优化 SQL、配置质量规则 |
| **数据分析师** | 快速取数、理解口径、自助查询 | 搜索表字段、NL2SQL 取数、查看数据质量报告 |

### 2.2 核心使用场景

**场景 A：找表找字段（分析师）**
> 分析师想找"最近3天每天下单的用户数"用什么表。他在平台搜索框输入"用户 下单 每日"或直接问自然语言，平台返回匹配的表/字段和推荐 SQL，并给出口径说明和数据质量评分。

**场景 B：建表建模（开发者）**
> 开发要新建一张主题宽表。平台读取已有 Hive 表结构，基于数仓规范（分层/命名/分区/ORC）自动生成建表 SQL，并给出规范校验结果与预警。

**场景 C：SQL 优化（开发者）**
> 开发提交一段慢 SQL，平台解析表依赖、获取元数据、结合 Spark 执行计划诊断瓶颈（如小文件、数据倾斜、Shuffle 过大），给出优化建议并可直接改写落地，最后对比评估。

**场景 D：质量保障（两者）**
> 平台对核心表配置质量规则（行数波动、主键唯一、非空率），调度后自动校验并生成报告，异常时告警。

**场景 E：口径问答（分析师）**
> 分析师直接提问"GMV 是怎么算的"，平台基于元数据 + 血缘 + 文档返回口径来源表与计算逻辑，避免口径不一致。

### 3.2 功能详情（FR 明细）

#### F1 元数据管理

**F1.1 Hive 表结构读取与同步**
- 支持读取**本地 Hive 建表语句 / SHOW CREATE TABLE / DESC FORMATTED** 获取表结构。
- 定时或手动全量/增量同步元数据。
- 支持指定库（如 hive 库）批量接入。

**F1.2 表/字段检索**
- 按表名、字段名、中文注释、关键字模糊检索。
- 支持按库、层级、主题筛选。
- 返回匹配度排序。

**F1.3 表详情**
- 展示字段列表（字段名/类型/注释/是否分区/是否主键）。
- 展示表大小、文件数、**小文件数**、行数、所有者、存储路径、存储格式。
- 展示分区信息。

**F1.4 血缘可视化**
- 表级血缘：上游表 → 下游表（含生成任务、调度状态、负责人）。
- 字段级血缘：字段级流向。
- 血缘图谱交互（缩放/聚焦/双击查详情）。

**F1.5 元数据快照与变更追踪**
- 记录每次同步的快照。
- 展示字段新增/删除/类型变更的 diff。

---

#### F2 智能建模

**F2.1 分层建模规范校验**
- 内置酒旅数仓规范（分层：dim/dwd/ads/etl/tmp/rpt；命名词根；分区规范；ORC 存储）。
- 对用户提交的建表语句自动校验并输出违规项（可配置规则库）。

**F2.2 建表 SQL 生成**
- 用户填写表名、中文注释、字段，或从已有表结构复制，自动生成符合规范的建表 SQL（含 PARTITIONED BY、STORED AS ORC、SNAPPY 压缩、字段注释）。

**F2.3 命名/分区/存储检查**
- 表名/字段名词根检查。
- 分区字段与分区粒度合理性检查。
- 存储格式（必须 ORC）检查。

**F2.4 模型推荐**
- 基于元数据 + 查询日志热度，推荐可建模主题域与字段组合（MVP 可简化为静态推荐）。

---

#### F3 SQL 智能开发助手

**F3.1 SQL 解析**
- 解析 SQL，提取涉及的表、字段、JOIN、WHERE、分区条件、特征（是否有 SELECT *、函数使用、笛卡尔积等）。
- 支持 Hive/Spark SQL 方言。

**F3.2 SQL 优化**
- **规则引擎**：内置 MUST DO / MUST NOT DO 规则（分区裁剪、列裁剪、小表广播、禁用 SELECT *、ORC 等）。
- **执行计划诊断**：接入 Spark History Server，分析 Job/Stage 耗时、Task 数、Shuffle 量、Input 量，定位瓶颈（数据倾斜、笛卡尔积、重复读表）。
- 输出结构化优化建议列表（含命中规则、原因、建议改写）。

**F3.3 SQL 改写与 Diff**
- 基于建议自动/半自动改写 SQL。
- 生成与原 SQL 的 Diff（行级），标记改动点。
- 保证**不改变查询语义**（禁止修改 WHERE 条件、禁止新增逻辑）。

**F3.4 优化效果评估**
- 多维度评估（执行性能、资源消耗、稳定性、成本效率、可维护性）。
- 优化前后对比报告与判定等级（优秀/良好/一般/不佳）。

**F3.5 语法/语义校验**
- 提交前进行语法校验与元数据校验（表/字段是否存在、类型匹配）。
- 输出错误行号与修复建议。

---

#### F4 数据质量

**F4.1 质量规则配置**
- 模板规则：非空率、主键唯一、行数波动、值域、枚举合法性、分区缺失。
- 支持自定义 SQL 规则。
- 规则可关联到表/字段/分区。

**F4.2 质量任务执行**
- 按调度触发（Spark 自带调度）或手动执行。
- 执行结果落库。

**F4.3 异常检测与告警**
- 规则不通过 / 波动超阈值时触发告警。
- 告警渠道（平台内通知 + 可扩展 IM）。

**F4.4 质量报告与评分**
- 生成表级质量评分与历史趋势。
- 按期（日/周）生成质量报告。

---

#### F5 智能检索问答

**F5.1 自然语言取数（NL2SQL）**
- 输入自然语言 → **调用外部 LLM（千问 Qwen 3.8，通过平台提供的 API）** 结合元数据 Schema 约束生成候选 SQL。
- 先生成 SQL 让用户确认，再执行返回结果（**安全：不直接执行非 SELECT**）。
- 平台对接千问 API，配置模型名/密钥/Endpoint；支持 schema 注入与 few-shot 提示词。
- 支持结果预览与下载。
- **安全边界**：LLM 仅用于生成/推荐 SQL，最终执行始终经过平台的只读校验（非 SELECT 拒绝）。

**F5.2 口径问答**
- 基于元数据 + 血缘 + 文档构建口径知识，回答问题并溯源；
- 底层接入千问 LLM 增强回答生成能力。

**F5.3 表/字段语义检索**
- 对表名、字段名、注释做向量化，支持语义相似检索（近义词/中文理解）。

**F5.4 结构化推荐**
- 检索结果附带相关表、字段、常用 SQL、质量信息，提高命中率。

---

#### F6 调度与任务

**F6.1 Spark 自带调度接入**
- 本期使用 Spark 自带调度（作业提交后由 Spark 负责执行）。
- 平台记录任务提交、状态、执行历史。

**F6.2 任务执行历史与日志**
- 展示每次执行的实例列表（实例ID、状态、耗时）。
- 可查看执行日志、Spark Application ID、Spark History 跳转。

**F6.3 依赖关系展示**
- 展示任务间 / 表间依赖。
- 支持查看某表的上游生成任务与下游使用任务。

**F6.4 调度框架扩展（预留）**
- 定义调度抽象接口（提交/取消/查询状态/日志），后续可接入 Azkaban / DolphinScheduler 等，本期不实现。

## 6. 总体技术架构

### 6.1 架构分层

```
┌─────────────────────────────────────────────────────────────┐
│                    前端展示层（Web）                         │
│  元数据浏览 / 建模引导 / SQL编辑器 / 质量看板 / 问答对话      │
└───────────────▲───────────────────────────────▲─────────────┘
                │ REST / WebSocket                │
┌───────────────┴───────────────────────────────┴─────────────┐
│                     应用服务层（后端）                        │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌────────┐ │
│  │元数据   │ │智能建模 │ │SQL助手  │ │数据质量 │ │检索问答 │ │
│  │模块     │ │模块     │ │模块     │ │模块     │ │模块    │ │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘ └────────┘ │
│  ┌──────────────────────────────────────────────────────┐   │
│  │          编排/任务/调度抽象层（可插拔）               │   │
│  └──────────────────────────────────────────────────────┘   │
└───────────────▲───────────────────────────────▲─────────────┘
                │                               │
┌───────────────┴───────┐        ┌──────────────┴─────────────┐
│   引擎/数据层          │        │   外部组件                 │
│  Spark (SQL执行/调度)  │        │  Hive Metastore           │
│  Spark History Server  │        │  Spark History            │
│  存储: MySQL/ES/向量库 │        │  本地Hive建表文件          │
└────────────────────────┘        └────────────────────────────┘
```

### 6.2 核心设计原则

1. **元数据驱动**：平台一切能力（建模、优化、检索、质量）都基于元数据。
2. **模块化可插拔**：数据源、调度、优化规则、NL2SQL 引擎均可替换扩展。
3. **查询安全**：平台内执行 SQL 默认仅只读（SELECT），写操作必须有明确确认。
4. **语义不变**：SQL 优化/改写严禁改变查询语义。
5. **本地可跑**：试点阶段可直接读取本地 Hive 建表语句，降低对接门槛。

## 7. 模块详细设计

### 7.1 元数据模块

**职责**：采集、存储、检索、展示元数据与血缘。

**采集流程（双模式）**：
```
模式一(本地文件)：Hive建表文件 → 解析器 → 标准化
模式二(直连)：Hive Metastore(jdbc) → SHOW CREATE/DESC → 标准化
统一汇入 → 入库(MySQL) → 建索引(ES) → 血缘加工(自建)
```

**存储**：
- MySQL：表、字段、分区、库等结构化元数据，含快照。
- ES：检索索引（表名/字段/注释）。
- 图/关系存储：血缘（MySQL 关联表或图数据库 Neo4j 可选，试点用 MySQL 关联表即可）。

**关键表**：见 8.3 数据模型（meta_database / meta_table / meta_column / meta_partition / meta_lineage / meta_snapshot）。

---

### 7.2 智能建模模块

**规范引擎**：规则可配置（JSON/表驱动），规则库示例：
- 命名规范：`[项目]_[主题]_[实体]_[周期+方式]`，词根校验。
- 分层库名映射（dim → dim_hotel 等）。
- 分区规范：分区字段（day/month/year/hour/area）、粒度。
- 存储规范：`STORED AS ORC` + `orc.compress=SNAPPY`。
- 注释规范：每个字段必须有 COMMENT。

**建表生成流程**：
```
表信息输入(名称/注释/字段/分区) → 规范规则校验 → 生成建表SQL模板 → 分区/存储/压缩自动填充 → 展示给用户确认
```

---

### 7.3 SQL 智能开发助手模块

**流程（S0–S8 控制器）**：
```
SQL输入 → S1解析(提取表/字段/特征) 
       → S2元数据关联(表大小/分区/格式) 
       → S3诊断(慢/倾斜/失败归因) 
       → S4执行计划(Spark History) 
       → S5优化器(规则匹配) 
       → S6改写(Diff) 
       → S7评估(五维对比) → 输出报告
```

**规则引擎**：
- MUST DO 规则（分区裁剪、列裁剪、谓词下推、小表广播、AQE 开启、ORC 等）。
- MUST NOT DO 规则（禁止 SELECT *、禁止分区字段套函数、禁止改 WHERE、禁止新增逻辑）。
- 规则以配置表管理，可启停。

**执行计划接入**：解析 Spark History 的 Jobs/Stages，提取 Stage 耗时、Task 数、Input/Shuffle 量，标识瓶颈 Stage。

---

### 7.4 数据质量模块

**规则模型**：规则 = 模板 + 参数 + 目标(表/字段/分区)。
- 模板：非空率、唯一性、行数波动(环比/同比)、值域、枚举、分区缺失。
- 自定义 SQL。

**执行**：质量校验 SQL（只读 SELECT 聚合）提交 Spark 执行，结果写入质量结果表。

**告警**：结果异常或波动超阈值 → 生成告警事件 → **平台内通知**（消息中心/在办提醒，集成 guanjia-message 平台内消息）。

---

### 7.5 智能检索问答模块

**NL2SQL（接入千问 Qwen 3.8）**：
- 主方案：**调用外部 LLM（千问 Qwen 3.8，平台提供 API）**，结合元数据 Schema 约束 + few-shot 提示词生成候选 SQL。
- LLM 网关层统一封装（模型名/密钥/Endpoint/nosql 配置），可热切换/降级。
- 安全兜底：LLM 生成的 SQL 必须经过只读校验（非 SELECT 拒绝）后才允许执行。
- 降级方案：LLM 不可用时退化为规则/模板 + 表结构感知生成（保留方案A）。

**语义检索**：表名/字段名/注释 → Embedding 向量 → 向量库检索。

**口径问答**：基于元数据 + 血缘 + 口径文档构建问答索引，底层接入千问 LLM 生成回答并溯源。

---

### 7.7 血缘模块（平台自建，表级）

**背景**：当前无现成血缘系统，平台在其上自建**表级血缘**。

**血缘来源**：
- 从已接入的 SQL（任务脚本、用户提交 SQL）中解析增量血缘存入 meta_lineage；
- 首次可通过离线解析历史 SQL 脚本批量回填；
- 后续新 SQL/任务提交时同步更新血缘。

**字段级血缘**：试点阶段暂不实现（仅在 meta_lineage 预留 field_level 字段），后续再增强。

**血缘加工流程**：
```
SQL/任务脚本 → SQL解析(提取输入/输出表) → 血缘写入(meta_lineage) → 图谱渲染
```

---

### 7.6 调度模块

**抽象接口**（可插拔）：
```
interface Scheduler {
  submit(task): TaskId
  status(taskId): TaskStatus
  cancel(taskId)
  logs(taskId): { applicationId, logUrl }
  history(taskId): ExecutionInstance[]
}
```

**Spark 自带调度实现**：作业直接提交 Spark，Spark 运行，平台通过 API/日志跟踪状态。此实现本期落地。

**扩展预留**：Azkaban / DolphinScheduler 实现同一接口，后续接入。

## 8. 数据模型设计

### 8.1 设计原则

- 统一以**库-表-字段**三层次建模，支持分区。
- 元数据与快照分离，支持变更追踪。
- 血缘以关联表存储，试点阶段不引入图数据库。

### 8.2 通用枚举

**分层枚举**：
| 值 | 说明 |
|----|------|
| dim | 维度层 |
| dwd | 明细层 |
| ads | 汇总应用层 |
| etl | 清洗中间层 |
| tmp | 临时层 |
| rpt | 对外报表层 |

**存储格式**：ORC / Parquet / Text（规范强制 ORC）。

**任务状态**：SUBMITTED / RUNNING / SUCCESS / FAILED / KILLED。

## 10. 技术选型与部署

### 10.1 技术选型

| 层 | 选型 | 说明 |
|----|------|------|
| 前端 | Vue3 / React + TypeScript + Monaco（SQL编辑器） | 交互体验好，Monaco 支持 SQL 智能提示 |
| 后端 | **Python(FastAPI)** | 已确认；对接大数据生态与 LLM 更便捷 |

| 元数据存储 | MySQL | 结构化元数据 |
| 检索 | Elasticsearch | 全文检索 |
| 向量 | Milvus / pgvector（可选） | 语义检索（迭代3） |
| 队列/异步 | Redis + Celery（适配 FastAPI） | 元数据同步、质量任务异步处理 |
| LLM | 千问 Qwen 3.8（HTTP API） | NL2SQL、口径问答 |
| 计算引擎 | Spark（**3.X**） | SQL执行、质量任务、调度 |
| 调度 | 本期 Spark 自带；预留 Azkaban/DolphinScheduler 接口 | 可插拔 |

### 10.2 部署形态（单团队试点）

```
前端 Nginx → Python(FastAPI) 后端服务(可单节点) → MySQL / ES / Redis

        ↘ 元数据采集：本地 Hive 建表文件 或 Hive Metastore 直连
        ↘ 调用千问 Qwen 3.8 LLM API（NL2SQL/口径问答）
```

- 试点阶段：后端单节点、数据库单实例即可满足 20 并发。
- 为后续扩展预留：模块化拆服务、队列解耦。

## 11. 风险与开放问题

### 11.1 风险清单

| 风险 | 等级 | 应对 |
|------|------|------|
| Hive 元数据量大，全量同步耗时长 | 中 | 增量同步 + 后台任务 + 分库批量 |
| 本地建表文件/直连两种模式结果需一致 | 中 | 统一标准化入库，落地校验 |
| 千问 LLM API 可用性与成本 | 中 | LLM 网关封装、可降级到规则生成、缓存 |
| LLM 生成 SQL 准确性/安全性 | 高 | 只读校验(非SELECT拒绝) + schema约束 + 用户确认 |
| 血缘自建（无外部系统）需冷启动 | 中 | 首次离线解析历史 SQL 批量回填，后续增量更新 |
| SQL 优化语义改变导致数据错误 | 高 | 严控规则（不改WHERE/不加逻辑）+ 前后校验闭环 |

### 11.2 已确认决策（2026-10-08）

| 决策项 | 结论 | 已落地章节 |
|--------|------|-----------|
| 后端技术栈 | Python(FastAPI) | §10.1 |
| 元数据采集 | 本地文件 + Hive 直连 双模式 | §7.1 / §9.3 |
| NL2SQL | 接入千问 Qwen 3.8 LLM | §7.5 / §9.3 |
| Spark 版本 | 3.X | §10.1 |
| 血缘 | 无外部系统，平台自建表级 | §7.7 / §9.3 |
| 告警通知 | 平台内通知 | §7.4 |

> 本文档已升级为 v1.0 决策确认稿，技术决策全部落地。后续可将每个接口的出入参、数据库 DDL、千问 LLM 网关交互协议细化，产出可直接开发的完整工程 Spec。
