# 知识库样例 —— 《国际酒店主题》文档 → NL2SQL 知识条目

> 演示目的：展示"一篇维基文档 → 一组可直接入库的知识条目"的完整转化流程。
> 源文档：https://toca.17u.cn/wiki?fid=873c30147e944fbc9f2360da4f2a8454
> 层级：UBT 新模型 → 国际酒店主题
> 转化工具：OpenClaw + tiexin-doc-claw（读取）→ 人工/半自动整理 → 入库

---

## 一、转化流程总览

```text
① 读取文档         ② 结构拆解          ③ 知识分类            ④ 生成入库条目
─────────        ─────────         ──────────          ──────────
维基 Markdown  →  核心输出表      →  mapping 表↔业务意   → JSON (kb_document/kb_alias)
 (markdown-      字段明细           mapping 枚举字典
  content)        主题Q&A           alias 字段同义词
                                   glossary 口径规则
```

**一条原则**：把文档里 **"用户会怎么问"** 和 **"系统该怎么答"** 的对应关系抽出来，做成 LLM 提示词里能直接看懂的结构化知识。

## 四、入库方式说明（对接 Spec 第 5 章）

入库 JSON 可通过以下任一方式写入：

1. **手动**：知识库管理页 → 逐条录入（POST /api/v1/kb/documents、/api/v1/kb/aliases）
2. **批量**：将上面的 JSON 通过批量导入接口写入后，触发向量重建（POST /api/v1/kb/embedding/rebuild）
3. **最佳实践**：入库后执行一次 `POST /api/v1/nl2sql/generate` 用真实问题（如"国际酒店宽表昨天UV"）验证召回是否正确命中知识条目

## 五、转化流程要点总结（可复用于其他文档）

对一篇维基文档做 NL2SQL 知识转化时：

1. **先读正文**：`tiexin-cli doc +markdown-content`
2. **识别三类知识**：
   - 表/枚举/业务词 → 映射 → `mapping`（kb_document）
   - 字段中文名/常用别名 → 同义词 → `alias`（kb_alias）
   - 口径/选表/数据路由规则 → `glossary`（kb_document）
3. **每条知识写清"用户会怎么问"**：content 里用【业务词→标准】格式，让 LLM 能直接套用
4. **打标签**：tags 用空格分词友好的中文词组，供关键词检索
5. **记录来源**：source 存 wiki 链接，便于溯源
